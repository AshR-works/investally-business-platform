## Réserves, limites et dette connues
- **Un mauvais code MFA était compté deux fois** contre le verrouillage du compte : mon client prenait le `401` pour un jeton expiré, se rafraîchissait puis **rejouait** la vérification. Découvert en lisant le journal réseau lors de la recette réelle (aucun test automatique ne pouvait le voir, car l'API seule se comporte correctement). Corrigé des deux côtés (en-tête RFC 6750 côté API, reprise conditionnelle côté client), testé et **vérifié de nouveau dans le navigateur** : une seule requête par tentative.
- **Page d'administration affichée à un utilisateur sans droit** (cadre visible, puis « Accès refusé » en bas de page) : la page vérifie maintenant les droits avant tout affichage ni appel.
- **Codes de secours perdus par un simple rechargement** pendant l'affichage unique : ajout d'un avertissement du navigateur avant de quitter la page (et possibilité de régénérer les codes depuis « Mon compte »).
- **Libellé d'appareil illisible** (User-Agent brut) : résumé en « Chrome sur Windows » (bulle d'aide avec le détail).
- **Tableau trop haut sur téléphone** (boutons d'action empilés) : largeur minimale de la colonne d'actions.
- **Incident d'environnement (mon fait)** : en redémarrant les serveurs de recette, la clé de chiffrement MFA de test avait été régénérée, rendant illisibles les secrets MFA enregistrés. Sans conséquence (base jetable), la clé est maintenant persistée pour la durée de la recette.
- **Aucun test automatisé des écrans** : les parcours ci-dessus ont été joués à la main dans un vrai navigateur (D22).
- **Pas de « mot de passe oublié »** (D21) : seul un administrateur peut renvoyer un lien à un compte en attente ; un compte actif qui perd son mot de passe n'a pas encore de parcours de récupération. **Décision attendue** (registre, D15).
- **Pas de vraie application d'authentification testée** : les codes de recette sont calculés par un programme (algorithme standard, vecteurs RFC validés en S3.2).
- **Pas de Microsoft 365** : l'invitation est lue dans la console de développement.
- CSP avec `'unsafe-inline'` pour les scripts (D20).
- Le rafraîchissement du jeton se fait au premier refus après 15 minutes (D24).
- Aucune adaptation de la durée de session côté interface : l'écran de connexion réapparaît quand la session absolue expire.
- Les écrans n'ont pas été relus par un spécialiste de l'accessibilité : étiquettes, focus, rôles `alert`/`status` et fenêtres modales sont en place, mais aucun lecteur d'écran n'a été utilisé.
