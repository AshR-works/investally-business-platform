Réserves, limites et dette connues

  • Tests d'intégration trop impatients (ma faute) : le traitement continue après la réponse (volontairement), mes premiers tests lisaient l'audit au bout de 300 ms et échouaient sur une machine lente. Les tests attendent maintenant l'e-mail ou l'audit (jusqu'à 15 s) et le délai d'un test est relevé à 30 s. La logique n'a pas changé.
  • Borne du plafond horaire : un lien créé pile une heure plus tôt compte encore. Le test le vérifie à la milliseconde plutôt que d'accepter une borne floue.
  • Commentaire périmé : main.ts affirmait que le MFA et le contrôle d'accès n'étaient « pas branchés » ; corrigé.
  • Mutant survivant M1 (voir ci-dessus) : test ajouté.
  • Premier passage complet des tests d'intégration sous charge : 4 échecs de délai (transaction non démarrée à temps, tests dépassant 5 s ou 60 s) dans des tests de S3.3, pendant que la machine exécutait d'autres tâches lourdes. Aucun n'a reproduit : la même suite passe seule (10/10) puis en entier au calme (141/141). Noté honnêtement comme fragilité de l'environnement de test (machine lente), pas comme défaut de code ; à surveiller.
  • Incident d'outil de recette : le navigateur intégré suspend les requêtes réseau quand son panneau est masqué (ERR_NETWORK_IO_SUSPENDED) ; une soumission de formulaire n'est pas partie. Elle a été rejouée panneau visible. Aucun lien avec le code livré, noté pour ne pas le confondre avec un défaut.
  • Microsoft 365 non testé : le lien est lu dans la console de développement (option réservée au développement, refusée en production).
  • Traitement après la réponse, en mémoire (D26) : une panne du processus entre la réponse et l'envoi perd la demande ; l'utilisateur redemande.
  • Nuisance possible (D25) : redemander des liens pour une adresse connue invalide le lien légitime de la victime (3 fois par heure au plus) ; tracé, non bloquant.
  • Pas de notification après un changement fait depuis « Mon compte » (D27).
  • Si le téléphone est aussi perdu, un administrateur doit en plus réinitialiser le MFA (D14) ; les deux actions sont possibles et tracées.
  • Les écrans restent vérifiés à la main (D22).
