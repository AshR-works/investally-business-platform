## Avant de commencer
- Réinitialiser la pile (`node scripts/local-stack.mjs reset`, puis `--seed=demo --rebuild`) ; comptes de démonstration (mots de passe dans le fichier local, jamais dans le dépôt).
- Rôles utiles : Responsable Investudy, Super administrateur, Direction, un chargé de compte.
- Préparer une session ouverte avec au moins un inscrit **confirmé** (le jeu de démonstration en contient ; sinon, inscrire et confirmer un apprenant depuis la fiche de session).

## Vérifications à rejouer
| N° | Vérification | Résultat attendu (d'après la recette) | Constaté (✔ / ✘) | Date et initiales |
|---|---|---|---|---|
| 1 | Qui clôture et rouvre | `training.session.close` et `training.session.reopen` : Responsable Investudy et Super administrateur seulement ; les autres rôles reçoivent 403 | ☐ | |
| 2 | Clôture : seule une session ouverte | Une session planifiée ou déjà clôturée refuse la clôture (422) ; après clôture, elle ne s'annule plus, ne se modifie plus, ne se reporte plus | ☐ | |
| 3 | Réouverture : motif obligatoire, tracé | Sans motif : 400 avant l'envoi ; avec motif : la session redevient « Ouverte », le motif est tracé dans l'audit, jamais stocké sur la session elle-même | ☐ | |
| 4 | Présences figées à la clôture | Toute saisie ou correction d'une présence est refusée (422) tant que la session est clôturée ; de nouveau possible après réouverture | ☐ | |
| 5 | Qui figure sur la feuille | Seuls les inscrits **confirmés** (en attente, annulés, à replacer : absents de la feuille) ; une colonne par jour de cours (lundi–vendredi) entre le début et la fin de la session, week-ends exclus même au milieu d'un rythme de plusieurs semaines | ☐ | |
| 6 | Une valeur parmi trois, aucune surveillance | Présent, en retard, absent ; ni heure, ni lieu, ni texte libre : la table et la réponse de l'API n'ont aucun champ pour cela ; un statut hors liste est refusé (400) | ☐ | |
| 7 | Idempotent, dernier auteur retenu | Resaisir la même valeur ne change rien et n'écrit rien dans le journal ; une correction par un autre compte écrit l'avant et l'après, et retient ce dernier auteur **en base** | ☐ | |
| 8 | Un jour hors période ou hors jour de cours | Un jour avant le début, après la fin, ou un week-end dans la période : refusé (400) | ☐ | |
| 9 | Qui saisit, qui lit | Saisie : Responsable Investudy et Super administrateur seulement — **jamais le formateur** (externe, sans compte, S1) ; lecture : les deux, et la Direction ; un chargé de compte n'a ni l'un ni l'autre | ☐ | |
| 10 | Une inscription hors de la session ou non confirmée | « Introuvable » (422/404 selon le cas), jamais une présence saisie sur une inscription qui n'appartient pas à cette session ou qui n'est pas confirmée | ☐ | |
| 11 | Règles garanties par la base | Une seule présence par inscription et par jour (index unique, conflit 409 au niveau du dépôt) ; clé vers l'inscription (jamais une présence sur une inscription inexistante) | ☐ | |
| 12 | Écran : feuille de présence | Un inscrit confirmé par ligne, une séance par colonne ; case cliquable avec dialogue à trois choix ; figée (lecture seule) une fois la session clôturée, avec message explicite | ☐ | |
| 13 | Écran : boutons Clôturer / Rouvrir | Visibles selon l'état et les droits, sur la liste et sur la fiche ; confirmation pour clôturer, motif obligatoire pour rouvrir | ☐ | |
| 14 | Preuves | Mutants : voir la recette (tués, survivants corrigés puis rejoués) ; collection Postman (parcours 90.6) : exécutée contre une pile jetable avec Newman | ☐ | |
