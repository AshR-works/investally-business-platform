## Avant de commencer
- Pile locale prête (`node scripts/local-stack.mjs --seed=demo --rebuild`) ; comptes de démonstration (mots de passe dans le fichier local, jamais dans le dépôt).
- Rôles utiles : Responsable Investudy, Super administrateur, Direction, un chargé de compte.
- Préparer une session ouverte (ou en cours) avec au moins un inscrit **confirmé**.

## Vérifications à rejouer
| N° | Vérification | Résultat attendu (d'après la recette) | Constaté (✔ / ✘) | Date et initiales |
|---|---|---|---|---|
| 1 | Une note sur 20, sans commentaire libre | `training.evaluation.record` : Responsable Investudy et Super administrateur seulement ; au plus une évaluation par inscrit **confirmé** ; un nombre hors 0-20 ou à plus de deux décimales est refusé (400) | ☐ | |
| 2 | Qui saisit, qui lit | Saisie : Responsable Investudy et Super administrateur — **jamais le formateur** (même règle que les présences, S1) ; lecture : les deux, et la Direction ; un chargé de compte n'a ni l'un ni l'autre | ☐ | |
| 3 | Figée à la clôture | Toute saisie ou correction est refusée (422) tant que la session est clôturée ; de nouveau possible après réouverture | ☐ | |
| 4 | Idempotent, dernier auteur retenu | Resaisir la même note ne change rien et n'écrit rien dans le journal ; une correction par un autre compte écrit l'avant et l'après, et retient ce dernier auteur **en base** | ☐ | |
| 5 | Une inscription hors de la session ou non confirmée | « Introuvable » (422/404 selon le cas), jamais une évaluation saisie sur une inscription qui n'appartient pas à cette session ou qui n'est pas confirmée | ☐ | |
| 6 | Qui figure sur la feuille | Seuls les inscrits **confirmés** (en attente, annulés, à replacer : absents) | ☐ | |
| 7 | Calcul du taux de présence (S3) | Un retard compte comme présent ; le taux est calculé sur les jours de cours de la session, pas sur les jours saisis seulement | ☐ | |
| 8 | Suggestion d'éligibilité, jamais de délivrance | Certificat : les deux seuils atteints (présence **et** note) ; attestation : seule la présence atteinte (note absente ou insuffisante) ; sinon aucune suggestion. La feuille ne délivre, ni ne révoque, rien (lot c) | ☐ | |
| 9 | Seuils paramétrables | `/training/thresholds` : lecture par tout détenteur de `training.evaluation.read` ; modification réservée à `training.evaluation.manage` (verrou optimiste, version périmée refusée avec 409) ; valeurs hors bornes refusées (400) | ☐ | |
| 10 | Règles garanties par la base | Au plus une évaluation par inscription (index unique, conflit 409 au niveau du dépôt) ; clé vers l'inscription ; note entre 0 et 20 (contrainte de la base) ; une seule ligne de seuils | ☐ | |
| 11 | Écran : feuille d'évaluation | Un inscrit confirmé par ligne, note, taux de présence et suggestion affichés ; bouton Saisir/Corriger selon l'état ; figée (lecture seule) une fois la session clôturée, avec message explicite | ☐ | |
| 12 | Écran : seuils d'éligibilité | Réservé à qui gère ; formulaire à deux champs, enregistrement avec confirmation ; les autres profils voient un message de restriction | ☐ | |
| 13 | Preuves | Mutants : voir la recette (35 tués sur 36, 1 survivant expliqué) ; collection Postman (parcours 90.7) : exécutée avec Newman | ☐ | |
