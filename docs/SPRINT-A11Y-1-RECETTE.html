Défauts trouvés et corrigés

#DéfautGravitéCorrection
1Même titre de page partout (« Investally CRM ») : un utilisateur de lecteur d'écran ne sait pas sur quelle page il est ni quand elle change (WCAG 2.4.2). Non détecté par l'outil automatique.MajeureComposant PageHeading : le h1 fixe aussi le titre du document, rétabli si Next.js le remplace après une navigation interne. Titres distincts pour les liens invalides (invitation / réinitialisation)
2Fond non inerte derrière les fenêtres : le commentaire du code l'annonçait, mais seul aria-modal y contribuait (non respecté par tous les lecteurs) ; Tab pouvait sortir de la fenêtre. Non détecté par l'outil automatique.MajeureModal : le reste de la page reçoit inert, Tab boucle dans la fenêtre, le focus est rendu à l'élément d'origine. Vérifié : 61 éléments lisibles avant, 19 après (fenêtre ouverte)
3Colonne d'actions de « Mon compte » sans nom (th vide) — détecté par axeMineureTexte réservé « Actions » (.sr-only)

Résultat final (après corrections)

  • 15 états audités, 0 violation, 0 point à vérifier à la main.
  • Langue du document fr partout. Les erreurs (role="alert") et confirmations (role="status") sont annoncées sans déplacer le focus. Les champs obligatoires sont annoncés comme tels. Le QR code a une alternative texte et la clé manuelle est disponible.
  • Tests de l'interface : 24/24 ; typage sans erreur. Détail état par état : accessibilite/resultats/lecteur-d-ecran-proxy-2026-10-21.md.

Reste à faire (dette D31)

  1. Écoute humaine du protocole (NVDA + Firefox au minimum, Narrator, puis VoiceOver).
  2. Brancher a11y-audit.mjs dans la CI quand une pile de test web sera disponible (aujourd'hui lancé à la main).
  3. Auditer les écrans du nouveau design à leur intégration (rail de navigation, hub, cartes d'opportunités ; toute interaction au glisser-déposer devra avoir une alternative clavier).
